# react-native-ssl-manager — Project Guide

## What This Is

Production-ready SSL certificate pinning for React Native and Expo (v2+: a
[Nitro Module](https://nitro.margelo.com)). Protects against MITM attacks using
platform-native enforcement on both iOS (TrustKit) and Android (OkHttp
`CertificatePinner` + Network Security Config).

Current version: **2.0.0**. Requires React Native 0.75+, New Architecture,
and `react-native-nitro-modules` as a peer dependency.

## Build, Lint, and Test Commands

```bash
# Install dependencies
yarn

# Type-check
yarn typecheck          # tsc --noEmit

# Lint
yarn lint               # expo-module lint
yarn lint --fix

# Unit tests
yarn test               # expo-module test (Jest, react-native preset)

# Generate native code from Nitro spec
yarn specs              # runs nitrogen

# Run example apps (bare React Native)
yarn example:ios
yarn example:android

# Run Expo example apps
yarn example-expo:ios
yarn example-expo:android
yarn example-expo:start
```

> **Important:** Use `yarn`, not `npm`. The project uses Yarn Berry (v3.6.1)
> workspaces. Run `corepack enable` if `yarn` isn't available.

## Key Architecture Decisions

### Nitro Module (v2)
The native bridge is generated by `nitrogen` from `src/specs/SslManager.nitro.ts`.
Run `yarn specs` after changing the spec to regenerate `nitrogen/`. The podspec
is named `NitroSslManager` (not the old `react-native-ssl-manager` name).

### Eager Initialization
Pinning is enforced **at app launch**, independent of JavaScript:
- **iOS**: Objective-C `+load` in `UseSslPinningModule.mm` calls
  `SharedLogic.bootstrapIfEnabled()` before React Native starts.
- **Android**: `SslPinningInitializer` (androidx.startup) installs the pinned
  `OkHttpClientFactory` before `Application.onCreate` completes.

### Runtime API
The JS exports in `src/index.ts` are the runtime control surface. All functions
throw (not no-op) when the native module is not linked. Guard with
`isSSLManagerAvailable()` if needed.

### TrustEngine
`TrustEngine` is a pure-TypeScript, platform-agnostic trust evaluator that
supports time-bounded SPKI pinning with a CAA-derived issuer fallback and grace
window. It complements the native layer's direct pinning with an optional
policy layer for cert-rotation scenarios. See `src/TrustEngine.ts` and
`src/types/TrustPolicy.ts`.

### iOS Caveats
- TrustKit can only be initialized **once per process**. Calling `setUseSSLPinning`
  or `setSSLConfig` on iOS persists the change; the new config takes effect on
  the **next app launch**.
- The podspec name changed to `NitroSslManager` in v2.

### Android NSC
- A `network_security_config.xml` is generated at build time from `ssl_config.json`.
- **Pins never expire** (no `pin-set expiration` attribute) — expiry was removed
  in v1.1.3/v2.0.0 because it was a silent fail-open.
- If the app already has an NSC file, the library merges pin-set entries.

## ssl_config.json Format

```json
{
  "sha256Keys": {
    "api.example.com": [
      "sha256/PRIMARY_SPKI_HASH=",
      "sha256/BACKUP_SPKI_HASH="
    ]
  }
}
```

Always include ≥ 2 pins per domain (primary + backup) to avoid lockout during
certificate rotation.
